## 1. Where everything lives

```
┌────────────────────────────────────────────────────────────────────────┐
│ VAULT                                                                  │
│                                                                        │
│  bare/data/           AUTHORITATIVE — immutable, content-addressed      │
│    obj-cas-imm-a1b2   blob    file bytes            (random IV)        │
│    obj-cas-imm-c3d4   tree    directory listing     (deterministic IV) │
│    obj-cas-imm-e5f6   commit  tree id + parents     (random IV)        │
│                                    ^                                   │
│                                    | deterministic IV = unchanged      │
│                                    | subtrees keep the SAME id         │
│                                    | (true CAS dedup)                  │
│                                                                        │
│  bare/refs/           MUTABLE — the head pointer                       │
│    ref-pid-muw-9a8b   "current" branch head  ──> commit id             │
│                                                                        │
│  bare/indexes/        DERIVED — this feature (never authoritative)     │
│    idx-pid-snw-3f9c   INDEX  ──> points at a blob / tree               │
│    idx-pid-snw-77ab   CACHE  ──> holds a COPY of the value            │
│                                                                        │
│  <working tree>       ORDINARY TRACKED CONTENT                         │
│    .sgit/indexed.json DECLARATION — which paths are indexed/cached     │
│    api-keys/ docs/ …  the user's files                                 │
└────────────────────────────────────────────────────────────────────────┘

   Rule: bare/indexes/* and .sgit/indexed.json are DERIVED or DECLARATIVE.
         Losing them costs performance, never correctness.
```

## 2. One derivation, two modes

```
                    path  +  read_key
                          │
                          ▼
      HMAC(read_key, "sg-vault-v1:file-id:path-index:{vault_id}:{path}")
                          │  [:12]
                          ▼
                  idx-pid-snw-3f9c          <-- computed LOCALLY, no lookup
                          │
             ┌────────────┴────────────┐
             ▼                         ▼
   ┌───────────────────┐     ┌───────────────────┐
   │      INDEX        │     │      CACHE        │
   │   "where is it"   │     │   "here it is"    │
   ├───────────────────┤     ├───────────────────┤
   │ points_to: blob   │     │ value: <bytes>    │
   │         or tree   │     │                   │
   │ commit_id         │     │ commit_id         │
   │ path, size, type  │     │ path, size, type  │
   └─────────┬─────────┘     └─────────┬─────────┘
             │                         │
      +1 read to fetch           0 extra reads
             ▼                         ▼
        the blob/tree              the value
                                                                    
   INDEX  = stable locator.  Risk: DANGLING  -> fixed by write order
   CACHE  = explicit copy.   Risk: STALE     -> fixed by commit_id + repair
```

## 3. Why it is worth doing — batching collapses breadth, not depth

```
 (a) TREE WALK to a known path              cost = DEPTH of the tree
 ─────────────────────────────────────────────────────────────────────
   client                                     server
     │  read ref                                │
     │ ────────────────────────────────────────>│   round trip 1
     │ <──────────────── commit id ─────────────│
     │  read commit                             │
     │ ────────────────────────────────────────>│   round trip 2
     │ <──────────────── tree id ───────────────│
     │  read root tree                          │
     │ ────────────────────────────────────────>│   round trip 3
     │ <──────────────── subtree id ────────────│
     │  read subtree                            │
     │ ────────────────────────────────────────>│   round trip 4
     │ <──────────────── blob id ───────────────│
     │  read blob                               │
     │ ────────────────────────────────────────>│   round trip 5
     │ <──────────────── VALUE ─────────────────│
                                                    ===============
                                                    5 ROUND TRIPS

   Batching cannot help: the next id is INSIDE the current encrypted object.


 (b) INDEX                                   cost = 2, depth irrelevant
 ─────────────────────────────────────────────────────────────────────
     │  compute id locally .............. no request
     │  read idx ──────────────────────────────>│   round trip 1
     │ <──────────────── blob id ───────────────│
     │  read blob ─────────────────────────────>│   round trip 2
     │ <──────────────── VALUE ─────────────────│


 (c) CACHE                                   cost = 1, depth irrelevant
 ─────────────────────────────────────────────────────────────────────
     │  compute id locally .............. no request
     │  batch read { ref, idx } ───────────────>│   round trip 1
     │ <────────── ref + VALUE (whole) ─────────│
                                                    ===============
                                                    1 ROUND TRIP
                              (the ref rides along free -> staleness check)
```

## 4. Write flow — content first, index last (additive phase)

```
  WORKING DIR          sgit push                        VAULT
  ───────────          ─────────                        ─────
                                                                     
  files ──────>  [ existing flow, UNCHANGED ]                        
                 build blobs + subtrees + tree                       
                       │                                             
                       ├── Phase A: write blobs ──────────> bare/data/
                       │                                             
                       ├── Phase B: write commits+trees ──> bare/data/
                       │                                             
                       └── write ref (WRITE_IF_MATCH/CAS) > bare/refs/
                                    │                                
                          ══════════╪═══════════ content now DURABLE 
                                    │                                
                 [ NEW flow, ADDITIVE — skipped if no declarations ]  
                                    │                                
                       ┌────────────┴─────────────┐                  
                       │ read .sgit/indexed.json  │                  
                       │ reconcile ALL declared   │                  
                       │   paths vs new head      │                  
                       └────────────┬─────────────┘                  
                                    │                                
                       ┌────────────┴─────────────┐                  
                       │ INDEX -> build pointer   │                  
                       │ CACHE -> build value copy│                  
                       │ gone  -> build delete op │                  
                       └────────────┬─────────────┘                  
                                    │                                
                       separate batch ──────────────────> bare/indexes/
                                                                     
  ORDER MATTERS:
    content -> ref -> index/cache
      * crash before index  => index merely LAGS   (safe, self-healing)
      * index written first => index points at NOTHING (unrecoverable)
    The cache must never lead its source of truth.
```

## 5. Read flow with fallback — correctness never depends on the cache

```
      compute idx id locally
              │
              ▼
      batch read { ref, idx }        <-- ONE round trip (breadth, not depth)
              │
              ▼
        ┌───────────┐
        │ idx found?│
        └─────┬─────┘
         no   │   yes
      ┌───────┘     └────────┐
      ▼                      ▼
 ┌─────────┐         ┌────────────────┐
 │ TREE    │         │ path matches?  │  (48-bit id collision guard)
 │ WALK    │<── no ──┤                │
 │(correct,│         └───────┬────────┘
 │ slower) │             yes │
 └─────────┘                 ▼
      ▲              ┌──────────────────────┐
      │              │ idx.commit_id == ref?│
      │              └───────┬──────────────┘
      │            yes       │        no
      │        ┌─────────────┘        └──────────────┐
      │        ▼                                     ▼
      │  ┌──────────────┐                  ┌──────────────────┐
      │  │ PROVABLY     │                  │ MAY BE STALE     │
      │  │ FRESH        │                  │ caller chooses:  │
      │  │ use it  ✅   │                  │  trust (fast) or │
      │  └──────────────┘                  │  verify ─────────┼──┘
      │                                    └──────────────────┘
      └─────────────────────────────────────────────
                    fallback is ALWAYS available

   Worst case is STALE-BUT-DETECTABLE. A wrong answer is never returned.
```

## 6. Where the declaration lives — and why

```
  THE QUESTION: where do we record "this path is indexed / cached"?

  ┌──────────────────────────────────────────────────────────────────┐
  │ OPTION C — new field on Schema__Object_Tree_Entry, always written │
  │                                                                  │
  │   entry: {blob_id, …, large, index_mode:null}   <-- null emitted  │
  │            │                                                     │
  │            └─> EVERY entry's bytes change                        │
  │                └─> EVERY tree id changes                         │
  │                    └─> CAS dedup vs all history BREAKS  ❌       │
  │                        old/new clients disagree on ids  ❌       │
  └──────────────────────────────────────────────────────────────────┘

  ┌──────────────────────────────────────────────────────────────────┐
  │ OPTION B — same field, version-gated (tree_v2)                    │
  │                                                                  │
  │   only declared entries change  (better)                         │
  │   BUT trees are REBUILT from the working dir every commit,       │
  │   and an OLD client's schema has no such field:                  │
  │                                                                  │
  │     new client writes  index_mode ──┐                            │
  │     old client commits ─────────────┴─> field DROPPED  ❌        │
  │     new client later   ─────────────> no record it existed ❌    │
  │                                        PERMANENT, SILENT         │
  └──────────────────────────────────────────────────────────────────┘

  ┌──────────────────────────────────────────────────────────────────┐
  │ OPTION A — ordinary tracked file: .sgit/indexed.json   ✅ CHOSEN │
  │                                                                  │
  │   old client does not need to UNDERSTAND it —                    │
  │   it snapshots the whole folder, so it carries the file          │
  │   through as CONTENT, unchanged.                                 │
  │                                                                  │
  │     new client writes declaration ──┐                            │
  │     old client commits ─────────────┴─> declaration PRESERVED ✅ │
  │     new client later   ─────────────> reconciles -> HEALED    ✅ │
  └──────────────────────────────────────────────────────────────────┘

  Schema knowledge is NOT required to preserve content. That is the trick.
```

## 7. Three layers — what is optimised and what is not

```
  ┌────────────────────────────────────────────────────────────────────┐
  │ LAYER 1  in-memory re-derivation                    NOT optimised  │
  │   commit scans the whole dir; make_entry() runs for EVERY file     │
  │   (no subtree short-circuit)                                       │
  ├────────────────────────────────────────────────────────────────────┤
  │ LAYER 2  object identity / storage / network        OPTIMISED  ✅  │
  │   that re-derivation is engineered to be BYTE-IDENTICAL, so        │
  │   unchanged subtrees produce the SAME obj-cas-imm-id               │
  │     -> nothing re-stored, nothing re-uploaded                      │
  │   (encrypt_deterministic + encrypt_or_reuse_blob)                  │
  ├────────────────────────────────────────────────────────────────────┤
  │ LAYER 3  field preservation                         NOT optimised  │
  │   entries are RECONSTRUCTED, not copied  ->  unknown fields die    │
  │   (this, and only this, drives the compatibility conclusion)       │
  └────────────────────────────────────────────────────────────────────┘

  Layer 1 is cheap PRECISELY BECAUSE layer 2 makes it produce identical bytes.
```

## 8. Blast radius — measured, not assumed

Vault under test. Edit is to `/docs/file-1.txt` **only**.

```
   /api-keys/api-key-1.json        <- INDEX declared
   /api-keys/api-key-2/data.json   <- CACHE declared
   /api-keys/api-key-2/info.md
   /docs/file-1.txt                <- THE EDIT
   /docs/file-2.md
   /other/thing.txt                <- control: undeclared, untouched


   tree                    NEW client        OLD client
   ─────────────────────────────────────────────────────────
   api-keys/api-key-2      same      ✅      CHANGED  ⚠ churn
   api-keys                same      ✅      CHANGED  ⚠ churn
   docs                    CHANGED (expected) CHANGED (expected)
   other  (control)        same      ✅      same     ✅
   root                    CHANGED (expected) CHANGED (expected)


   Two DIFFERENT radii — do not confuse them:

     DECLARATION LOSS ......... VAULT-WIDE
        every declared path loses its flag, wherever the edit happened

     TREE CHURN ............... SCOPED
        only trees containing declared entries + their ancestors;
        `other` keeps its id under BOTH clients

   Second cost of Option B, in performance terms:
     an old-client commit DEFEATS CAS dedup for exactly the subtrees
     you cared enough to declare -> they get re-stored and re-uploaded.
     Option A causes none of this (entries stay byte-identical).
```

## 9. Mixed-version timeline — self-healing (Option A)

```
  TIME ─────────────────────────────────────────────────────────────────>

  new sgit push
    │ cache(keys/api.json) written @ C1
    ▼
  ┌──────────────────────────────────────────┐
  │ reader: batch{ref,cache} -> both C1      │  FRESH, 1 round trip  ✅
  └──────────────────────────────────────────┘

  OLD sgit / OLD web edits the file, pushes  -> head = C2
    │ declaration (.sgit/indexed.json) preserved — it is just content ✅
    │ cache object untouched                 -> now STALE
    ▼
  ┌──────────────────────────────────────────┐
  │ reader: batch{ref,cache} ref=C2 vs C1    │  STALE DETECTED
  │         -> falls back to tree walk       │  CORRECT data, slower ✅
  └──────────────────────────────────────────┘

  new sgit push (ANY change)
    │ reconcile ALL declared paths vs head   -> rewrite drifted entries
    ▼
  ┌──────────────────────────────────────────┐
  │ reader: batch{ref,cache} -> both C3      │  HEALED, fresh again  ✅
  └──────────────────────────────────────────┘

  KEY: reconcile ALL DECLARED paths, not just this push's diff —
       the foreign write happened in SOMEONE ELSE'S push, so a
       diff-only rule would never revisit it.
```

## 10. Rollout — build in sgit, then replicate

```
   ┌──────────────────┐   derivation +   ┌──────────────────┐
   │  1. sgit (CLI)   │   schemas +      │  2. SG/Send API  │
   │                  │   TEST VECTORS   │     ("manager")  │
   │  * derivation    │ ───────────────> │                  │
   │  * INDEX/CACHE   │                  │  * read fast path│
   │  * push phase    │                  │  * IF IT WRITES: │
   │  * repair        │                  │    same invariant│
   └────────┬─────────┘                  └────────┬─────────┘
            │                                     │
            │                                     ▼
            │                            ┌──────────────────┐
            │      must match            │  3. Vault web    │
            └───── byte-for-byte ───────>│     (web sgit)   │
                                         │  * read fast path│
                                         └──────────────────┘

   The TEST VECTORS are the contract. Nothing is "done" until all
   three runtimes derive the same id and parse the same object.

   ⚠ A writer that skips index maintenance produces SILENT,
     PERMANENT staleness. If the manager API writes vaults,
     the maintenance invariant must live there too.
```

## 11. The rules, condensed

```
  1. INDEX = pointer ("where is it").  CACHE = copy ("here it is").
  2. Both are DERIVED. Never authoritative. Rebuildable from the tree.
  3. Content first, ref, THEN index/cache. The cache never leads.
  4. Declaration lives in a TRACKED FILE, never in the tree entry.
  5. Reconcile ALL declared paths on every push — not just the diff.
  6. Record commit_id: it makes staleness measurable instead of invisible.
  7. Always keep the tree-walk fallback. Correctness must not depend
     on an index existing or being fresh.
  8. Declared, not universal — every indexed path is a permanent
     write cost.
  9. Empty declaration file => the whole feature is a NO-OP.
```
