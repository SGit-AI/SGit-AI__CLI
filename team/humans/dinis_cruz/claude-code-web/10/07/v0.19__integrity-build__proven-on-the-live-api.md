# The integrity release, built and proven on the live API

**Date:** 7 Oct 2026 · **Branch:** `claude/charming-babbage-5hzcxq` · **Ask:** "do all the changes in
one CLI release, push it, and test against the live API whether anything breaks (for example the
longer ids); map whether this addresses the concerns raised at the start."

## 1. What is in the release

| Change | Command / behaviour | Old client on the same vault | Today's web UI |
|---|---|---|---|
| Format gate | `sgit vault format [--set 2] [--min-client X.Y.Z] [--feature F]`; read on every index load | ≤ 0.18 ignores the fields (fails open); a gate-aware client refuses by name | overwrite drops the gate; the next CLI pull restores it |
| 128-bit ids | new objects `obj-cas-imm-<32 hex>` on a format-2 vault; old objects untouched; every id verified at its own width | ≤ 0.18 **crashes on the first 32-hex id** (`Safe_Str__Object_Id` max 24): this is the one hard break, and what `--min-client` is for | reads both widths (confirmed by their research); writes 12-hex ids for new objects (allowed) until `computeObjectId` is format-aware |
| Shared index | pull and push merge the remote index and write with compare-and-swap | unaffected (still blind writes, as today) | its overwrite is repaired on the next CLI pull |
| Ref monotonicity | `status` reports a rewind; `pull` refuses; `pull --accept-rewind` takes it | unaffected | its unconditional push can cause real rewinds, which the CLI now reports (correctly) |
| Signature verification | `sgit check verify`; `fsck` summary; `signatures-required` enforced on pull; `migrate apply` guarded | unaffected (never verified) | its commits are unsigned: visible under verify, blocked only under `required` |
| Canonical signing input, `author_key_id` | since the previous commit on this branch | unaffected | the vector they need is in `tests/_fixtures/interop_vectors.json` |

Suite: `pytest tests/unit -n auto` → **3,976 passed** (16 new tests in
`tests/unit/review/test_Format_Gate_And_Integrity.py`, two real clones over the in-memory API).

## 2. Proven on the live dev API (dev.send.sgraph.ai, token in hand, throwaway vault `th8bfzj1`)

| Step | Result |
|---|---|
| seed commit, push at format 1 | `Push complete` |
| `sgit vault format --set 2 --min-client 0.1.0` | index written with `write-if-match` on the real server: `Format: 2 (new objects get 32-hex ids)` |
| commit + push at format 2 | server store: 16 objects, 9 at 12 hex, 7 at 32 hex; `read` of each wide id OK; `batch_read` of all 7 OK; `list` returns both widths |
| fresh clone of the mixed-id vault | 2.7 s; files present; `fsck`: `Checked 3 commits, 9 trees … Signatures: 3 verified … Vault OK`; `check verify`: 3 verified |
| stale `write-if-match` probe | the server answers **HTTP 200 with `results[0].status = "conflict"` and `current` = the stored bytes**; the in-memory API answers with a top-level `status: conflict`. The upload path now treats both as a conflict and retries as a merge (it read the per-op shape as success before this probe) |
| named ref rewound on the server to the parent commit | `status`: `the named branch was REWOUND or rewritten on the server …`; `pull`: refused, nothing changed; `pull --accept-rewind`: accepted, then `1 commit ahead` (correct: pushing restores it) |
| web-UI-style index overwrite (one entry, no gate) | `pull`: `Branch index: restored 2 entries the remote copy had lost`; server index back to 3 branches, format 2, `ids-128` |
| the big vault, scoped shallow clone with the new client | 14.9 s, `in sync`, format 1, no change in behaviour |

The throwaway vault is left on the server on purpose: its key is in the session's scratchpad, and
opening it in the vault web UI is the quickest way to see the read side of a format-2 vault.

## 3. A latent 0.18.0 bug the build exposed

`sgit status` has fetched commit objects (to count ahead/behind) since 0.18.0, and `pull`'s commit
walk skipped any parent that was already local, so the trees of those commits were never fetched:
a clone 4 commits behind that ran `status` then `pull` had 3 missing trees in `fsck`. The walk now
treats a local commit as complete only when its root tree is local. Test:
`test_pull_after_status_leaves_no_missing_trees`.

## 4. Does this address the concerns raised at the start?

| Concern (first message of the session, and the integrity question) | Where it stands |
|---|---|
| The big vault could not be cloned in a practical time; "don't create too many files or you'll break sgit" | 0.18.0: full clone 170 s → 80 s, scoped clone 14 s, two folders 5 s. The guidance can be retired; agents report it. |
| Releases not reaching PyPI | 0.18.0 published from the PR merge; the pipeline publishes on every dev → main merge. |
| Pull discarding uncommitted edits (10-agent team) | fixed in 0.18.0, with the guard proven from the decrypted blob. |
| "Always detect corruption of history" | against the host: yes, before and after (content addresses + AES-GCM; `fsck` now 12 s not 270 s). Against a key holder: the 48-bit second-preimage is closed on format-2 vaults; existing vaults keep their 48-bit ids until raised (no move needed). |
| "Detect a malicious or unauthorized commit" | signatures are now verifiable (`check verify`, `fsck`), carry their key id, and can be required per vault. "Unauthorized" still means "not signed by a key in the index": the web UI must sign before `required` is usable on vaults it writes to. |
| Rollback / rewritten history | detected and refused (rewind), accepted explicitly after a force push. A signed ref log would make it tamper-*evident* rather than tamper-*detected-by-clients*; not in this release. |
| Rekey without losing history | `vault move` rewrites every id and re-encrypts; history stays, old signatures do not verify after it (now visible). Format 2 does not need a move. |
| Forward compatibility without forcing a move | the gate: existing vaults untouched; raised vaults refuse old clients by name; mixed ids. The one break (≤ 0.18 crash on a 32-hex id) is bounded by raising vaults only once their writers are on the gate-aware release. |
| API and web UI side effects | API: none, confirmed by their research and by this run. Web UI: read side fine; its index overwrite is now repaired by the CLI; `computeObjectId`, deterministic trees, `pushIfMatch` and signing are theirs to do, in that order. |

## 5. Still open

- This release is **0.19.0**: the pipeline bumps the minor on each merge to main, and the 0.19 /
  0.20 split planned earlier collapsed into one release. `--min-client 0.19.0` is the value to use
  when raising a vault.
- `Vault__Batch.execute_batch` documents "raises on CAS conflict" but returns the body; the push
  path still reads a per-op conflict as success on the live server. Same fix as the index path;
  not done here.
- Web UI: `computeObjectId` format-aware, read the gate, deterministic tree IV, `pushIfMatch`,
  per-device signing keys, in the order of their reply.
